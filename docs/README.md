# Linux BSP 学习文档入口

这个目录优先保存整个仓库的导航、规范和跨模块资料；各模块正文不再直接散放在 `docs/` 根层。

## 模块入口

- [V4L2、Camera 与 PXP](../notes/09-v4l2/README.md)

后续学习 GPIO、I²C、SPI、USB 等模块时，在各自的 `notes/<编号-模块>/README.md` 中建立入口，再从这里增加一条链接。

## 统一存放规则

| 内容类型 | 存放位置 | 示例 |
|---|---|---|
| 全仓库导航、统一规范 | `docs/` | 本文件 |
| 某模块的阅读入口 | `notes/<模块>/README.md` | `notes/09-v4l2/README.md` |
| 不依赖具体板卡的通用原理 | `notes/<模块>/architecture/` | V4L2 Core、vb2、Media Controller |
| 具体板卡和芯片的适配实战 | `notes/<模块>/cases/<平台-器件>/` | i.MX6ULL + OV5640 |
| 可编译源码和实验程序 | 对应模块的源码目录 | `notes/09-v4l2/ov5640_camera_test/` |
| 厂商原始资料、移植源码包 | `hardware/<器件>/` | `hardware/ov5640/` |

## 判断一份新资料放在哪里

1. 如果脱离具体开发板仍然成立，放入当前模块的 `architecture/`。
2. 如果包含具体DTS、寄存器、驱动版本、上板日志，放入 `cases/<平台-器件>/`。
3. 如果是程序或驱动源码，不塞进Markdown文档目录，放在模块源码目录。
4. 同一事实只选一份文档作为“主解释”，其他文档通过链接引用，避免复制多份后内容不一致。

## 文件命名

- 阅读顺序明确的课程使用数字前缀：`00-`、`01-`、`02-`。
- 通用原理名称不带具体板卡。
- 实战文档标题必须体现平台、器件或驱动。
- 临时排查结论先写入对应案例，验证后再提炼到通用原理。
