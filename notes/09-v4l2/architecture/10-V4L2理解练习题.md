# V4L2 理解练习题

这份练习题配合下面两部分一起看：

- [简单 V4L2 设备驱动编写](05-简单V4L2设备驱动编写.md)

练习目标不是背 API，而是训练你在脑子里跑通这几条线：

```text

```

建议做法：先不看答案，自己口述一遍；讲不顺的地方，再回到代码里找对应函数。

## 2. buffer 流转题

### 2.1 空桶/满桶模型

请你用“空桶/满桶”解释下面流程：

```text
REQBUFS
QUERYBUF
mmap
QBUF
STREAMON
硬件完成一帧
vb2_buffer_done
DQBUF
再次 QBUF
```

重点说清楚：

```text
QBUF 时 buffer 在谁手里？
DQBUF 时 buffer 在谁手里？
vb2_buffer_done 前后发生了什么？
```

### 2.2 判断方向

判断下面说法对不对，错了就改正：

```text
1. QBUF 是 APP 从驱动取出一帧。
2. DQBUF 是 APP 把空 buffer 交给驱动。
3. buf_queue 被调用时，说明 APP 交来了一个空 buffer。
4. vb2_buffer_done 被调用后，APP 才有机会 DQBUF。
5. STREAMON 后 APP 一定立刻拿到一帧。
```

## 8. 面试式理解题

### 8.1 为什么 `v4l2_file_operations` 多数用现成函数？

回答时包含：

```text
标准入口
复用 V4L2/vb2 通用逻辑
驱动只在 ioctl_ops/vb2_ops 提供差异化行为
```

### 8.2 为什么标准函数还要驱动声明？

回答时包含：

```text
fops 是接线表
不是所有 V4L2 设备都支持同样入口
驱动可以直接用标准函数，也可以包一层
```

### 8.3 `v4l2_ioctl_ops` 和 `vb2_ops` 的区别是什么？

提示：

```text
v4l2_ioctl_ops：回答 APP 的 V4L2 命令。
vb2_ops：vb2 在 buffer 生命周期关键点回调驱动。
```
