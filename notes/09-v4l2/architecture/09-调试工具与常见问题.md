# 调试工具与常见问题

## 1. 分层调试原则

不要一上来就运行完整 APP，然后对着“poll timeout”猜。

推荐顺序：

```text
1. 设备是否枚举、驱动是否 probe
2. media topology 是否正确
3. subdev pad format/link 是否正确
4. video node capability/format 是否正确
5. buffer 是否成功申请和入队
6. streamon 是否真正启动各模块
7. 中断/URB/DMA 是否产生
8. vb2_buffer_done 是否发生
9. APP 是否及时 DQBUF/QBUF
10. 图像内容和颜色格式是否正确
```

## 2. `v4l2-ctl`

列出设备：

```sh
v4l2-ctl --list-devices
```

设备信息：

```sh
v4l2-ctl -d /dev/video0 -D
v4l2-ctl -d /dev/video0 --all
```

格式：

```sh
v4l2-ctl -d /dev/video0 --list-formats-ext
v4l2-ctl -d /dev/video0 --get-fmt-video
v4l2-ctl -d /dev/video0 \
  --set-fmt-video=width=640,height=480,pixelformat=YUYV
```

controls：

```sh
v4l2-ctl -d /dev/video0 -l
v4l2-ctl -d /dev/video0 -L
v4l2-ctl -d /dev/video0 -C brightness
v4l2-ctl -d /dev/video0 -c brightness=128
```

抓帧：

```sh
v4l2-ctl -d /dev/video0 \
  --set-fmt-video=width=640,height=480,pixelformat=YUYV \
  --stream-mmap=4 \
  --stream-count=100 \
  --stream-to=frames.yuyv
```

显示每帧统计：

```sh
v4l2-ctl -d /dev/video0 \
  --stream-mmap --stream-count=100 --stream-poll
```

## 3. `media-ctl`

查看 topology：

```sh
media-ctl -p -d /dev/media0
media-ctl --print-dot -d /dev/media0 > media.dot
dot -Tpng media.dot -o media.png
```

重置可配置 links：

```sh
media-ctl -r -d /dev/media0
```

启用 link：

```sh
media-ctl -d /dev/media0 \
  -l '"sensor":0 -> "csi":0 [1]'
```

设置 pad format：

```sh
media-ctl -d /dev/media0 \
  -V '"sensor":0 [fmt:SRGGB10_1X10/1920x1080]'
```

调试时把 `media-ctl -p` 输出保存下来，比只记 `/dev/video0` 有用得多。

## 4. `v4l2-compliance`

```sh
v4l2-compliance -d /dev/video0
```

它用于检查驱动是否遵守 V4L2 API：

- capability。
- format 枚举和 TRY/S/G 一致性。
- controls。
- buffer queue。
- streaming 状态机。

失败不一定直接说明硬件坏了，常常暴露的是驱动 API 语义错误，例如：

- 不支持的 index 没返回 `EINVAL`。
- S_FMT 后返回值不完整。
- queue busy 时仍允许改格式。
- streamoff 未正确回收 buffer。

## 5. `yavta`

`yavta` 是常用的轻量 V4L2 测试工具：

```sh
yavta -c100 -n4 -f YUYV -s 640x480 /dev/video0
```

不同版本参数可能不同，以 `yavta --help` 为准。它适合观察：

- 实际申请 buffer 数。
- 每帧 sequence、timestamp、bytesused。
- DQBUF 是否持续工作。

## 6. 内核日志和动态调试

基础日志：

```sh
dmesg -w
```

动态调试（内核启用 `CONFIG_DYNAMIC_DEBUG` 时）：

```sh
mount -t debugfs none /sys/kernel/debug
echo 'file drivers/media/* +p' \
  > /sys/kernel/debug/dynamic_debug/control
```

范围应尽量缩小到目标驱动，避免海量日志改变时序：

```sh
echo 'file drivers/media/usb/uvc/* +p' \
  > /sys/kernel/debug/dynamic_debug/control
```

## 7. trace

内核开启对应 tracepoints 时，可从：

```sh
ls /sys/kernel/debug/tracing/events
```

寻找 v4l2、vb2、irq、dma 等事件。厂商 4.9 内核的 tracepoint 集合差异较大。

即使没有专用 vb2 tracepoint，也可结合：

- function tracer。
- IRQ trace。
- 驱动临时 trace_printk。
- 中断计数 `/proc/interrupts`。

## 8. 常见问题表

| 现象 | 优先检查 |
| --- | --- |
| 没有 `/dev/videoX` | probe、`video_register_device` 返回值、media 聚合绑定是否 complete |
| 有 video 节点但无格式 | ioctl ops 是否实现、节点类型是否正确 |
| `REQBUFS` 失败 | `queue_setup`、mem ops、`q->dev`、sizeimage、DMA 内存 |
| `QBUF` 失败 | type/memory/index、plane 数、buffer 大小、buf_prepare |
| `STREAMON` 返回 `EINVAL` | 入队 buffer 不足、queue type 错、上游格式/link 不一致 |
| `STREAMON` 返回硬件错误 | 时钟/供电、Sensor ID、lane、link frequency、DMA |
| `poll` 超时 | 没中断/URB、active list 空、未调用 buffer_done、pipeline 未启动 |
| DQBUF 后 `bytesused=0` | 完成路径没设置 payload，压缩帧长度解析错误 |
| 很快停住 | APP 没重新 QBUF，驱动漏归还 buffer |
| sequence 跳变 | 丢帧、无 buffer、硬件 overflow、USB 包丢失 |
| 花屏/斜屏 | width/stride/bytesperline/sizeimage 不一致 |
| 颜色异常 | YUYV/UYVY/NV12 混淆、colorspace/quantization、Bayer 顺序 |
| 第一帧正常后卡死 | 下一 buffer DMA 未启动、IRQ 未清、队列竞态 |
| STREAMOFF 卡死 | IRQ/worker 未停止、锁死、active buffer 未归还 |
| 第二次 STREAMON 失败 | stop 路径未复位硬件/queue 状态 |

## 9. poll 超时的逐层定位

### 9.1 APP 层

- STREAMON 是否成功？
- 是否至少 QBUF 了 2～3 个 buffer？
- fd 是否误用错误节点？
- timeout 是否过短？

### 9.2 vb2 层

- `buf_queue` 是否被调用？
- `start_streaming` 是否被调用？
- queued/active 数量是多少？
- 是否调用过 `vb2_buffer_done()`？

### 9.3 硬件层

- Sensor 是否真的 stream on？
- MIPI clock/data lane 是否活动？
- CSI 是否报 ECC/CRC/FIFO error？
- `/proc/interrupts` 计数是否增长？
- DMA 地址和长度是否正确？

### 9.4 完成层

- IRQ 是否 ack？
- 当前 buffer 是否从 active list 摘除？
- payload/sequence/timestamp 是否填写？
- 是否在错误状态下仍完成旧 buffer？

## 10. 花屏的定位

先计算理论数据量：

```text
YUYV 640×480：
bytesperline = 640 × 2 = 1280
sizeimage = 1280 × 480 = 614400
```

然后逐项比对：

- Sensor 输出尺寸。
- CSI/ISP/Scaler pad 尺寸。
- Capture memory format。
- DMA line stride。
- vb2 plane size。
- `bytesused`。
- APP 按什么格式解释。

如果每行逐渐倾斜，多半是 stride 错；整体颜色怪但几何正确，多半是像素排列或色彩空间问题。

## 11. MIPI 特有检查

```text
Sensor：
  chip ID、xclk、regulator、reset、mode 寄存器、stream bit

物理链路：
  lane 数/顺序、极性、速率、连续/非连续时钟

CSI-2：
  virtual channel、data type、ECC/CRC、frame start/end

内部 pipeline：
  links enabled、pad format 一致、ISP bypass/工作模式

Capture：
  DMA stride、buffer 地址、IRQ、overflow
```

## 13. 总结

V4L2 调试也遵循架构边界：

```text
节点/API 问题 → V4L2 Core
buffer/等待问题 → vb2
参数问题 → controls/subdev
连接问题 → Media Controller
无数据/坏数据 → Sensor、CSI、ISP、DMA、USB
```
