# i.MX6ULL + OV5640：V4L2 完整调用链考核复习

> 状态：课程目录已建立，正文按阶段逐章完成。
>
> 学习规则：每次只学习一个阶段。完成本阶段的源码对应、口述检查和问题修正后，再进入下一阶段。

## 0. 文档目标

这份文档不再把 V4L2、VB2、Media、Subdev、CSI 和 Sensor 当成互不相关的知识点，而是围绕 i.MX6ULL + OV5640 的真实采集过程，贯通以下完整主线：

~~~text
APP
  → 系统调用 ioctl/mmap/poll
  → V4L2 Core
  → v4l2-ioctl ioctl 分发
  → videobuf2 Buffer Core
  → mx6s_capture（Video Node / CSI Host）
  → V4L2 Subdev
  → ov5640_v3（Sensor）
  → DVP
  → i.MX6ULL CSI + DMA + 中断
  → VB2 完成 Buffer
  → poll + DQBUF 返回 APP
~~~

完成复习后，需要能够脱离文档回答：

1. `/dev/video1` 是谁创建的，为什么不是 OV5640 创建的？
2. `ioctl(fd, VIDIOC_S_FMT, ...)` 怎样从 APP 到达 `mx6s_capture.c`？
3. `mx6s_capture` 和 `ov5640_v3` 在整个 V4L2 Pipeline 中分别是什么角色？
4. 为什么 APP 只对 `/dev/video1` 执行一次 `STREAMON`，却可以同时启动 CSI 和 OV5640？
5. `REQBUFS、QUERYBUF、mmap、QBUF、STREAMON、DQBUF` 分别改变了什么？
6. 一块 Buffer 在 APP、VB2、CSI DMA 之间怎样流转和改变所有权？
7. OV5640 没有采集循环和帧中断处理代码，为什么仍会连续输出图像？
8. CSI 中断怎样把一帧完成事件传递给 VB2，最终唤醒 APP 的 `poll()`？
9. Media Graph、endpoint、异步 notifier 和 `v4l2_subdev` 怎样把 CSI 与 OV5640 连接起来？
10. 花屏、无 `/dev/video1`、`S_FMT: No such device`、`DQBUF` 卡住分别应该从哪一层检查？

## 1. 复习方法

每个阶段固定采用五层讲法：

1. **先讲角色**：这个模块为什么存在，在架构中负责什么。
2. **再讲对象**：关键结构体是什么，谁持有谁，生命周期是什么。
3. **再讲入口**：上一层调用哪个接口，怎样进入本层。
4. **再讲源码**：对应当前 Linux 4.9.88 的具体文件、函数和关键成员。
5. **最后口述**：使用考核题验证是否真正理解，而不是只记函数名。

每个阶段结束时记录三种状态：

- `[已理解]`：能够自己画图并口述调用链。
- `[待复习]`：主线理解，但关键结构体或函数还记不清。
- `[未通过]`：角色、数据方向或调用关系仍然混淆，需要重讲。

## 2. 全课程阶段计划

### 阶段 1：总体架构和模块角色

目标：先建立完整地图，避免进入源码后迷失。

需要讲清：

- Linux 摄像头 Pipeline 中 APP、Video Node、V4L2 Core、VB2、Media、Subdev、CSI Host、Sensor 的位置。
- 控制路径、数据路径、Buffer 路径三者的区别。
- `mx6s_capture` 为什么是 Bridge/Host/Video Device，`ov5640_v3` 为什么是 Sensor Subdev。
- `/dev/video1`、`struct video_device`、`struct v4l2_device`、`struct v4l2_subdev`、`struct media_entity` 的第一层关系。

通过标准：能够不看文档画出总架构图，并解释每个模块的一句话职责。

### 阶段 2：APP 到 V4L2 Core 和 ioctl 分发

目标：彻底回答“APP 的 ioctl 到底怎样进入具体驱动”。

需要讲清：

- `open/ioctl/mmap/poll` 的角色。
- `video_device`、`v4l2_file_operations`、`v4l2_ioctl_ops`。
- `video_ioctl2()`、`video_usercopy()`、`v4l2_ioctls[]`。
- `VIDIOC_S_FMT` 如何进入 `v4l_s_fmt()`，再根据 `format.type` 选择回调。
- `mx6s_capture` 怎样把自己的函数注册给 V4L2 Core。

通过标准：能够独立跟踪 `VIDIOC_QUERYCAP` 和 `VIDIOC_S_FMT` 两条调用链。

### 阶段 3：videobuf2 Buffer Core

目标：不仅会背 ioctl 顺序，还能解释每一步的对象、状态和所有权。

需要讲清：

- `struct vb2_queue`、`struct vb2_buffer`、`struct vb2_v4l2_buffer`。
- 驱动自己的 Buffer 怎样嵌入 VB2 Buffer。
- `REQBUFS → QUERYBUF → mmap → QBUF → STREAMON → poll → DQBUF → QBUF`。
- Buffer 的 `DEQUEUED、QUEUED、ACTIVE、DONE` 等状态变化。
- VB2 Core 与 `mx6s_capture` 的 `vb2_ops` 怎样互相调用。

通过标准：能够跟踪一块 Buffer 从申请到反复采集的完整生命周期。

### 阶段 4：Media、V4L2 Subdev 和异步绑定

目标：理解 `/dev/video1` 背后的 Pipeline 怎样在启动前被建立。

需要讲清：

- 为什么 Sensor 通常不直接提供 `/dev/videoX`。
- `v4l2_subdev`、`media_entity`、`media_pad`、`media_link`。
- 设备树 `port/endpoint/remote-endpoint` 描述的是什么。
- CSI Host 怎样找到远端 Sensor。
- `v4l2_async_notifier` 的 match、bound、complete。
- `csi_dev->sd` 是什么时候、由谁赋值的。

通过标准：能够解释“设备树只描述连接，驱动如何把连接变成运行时指针”。

### 阶段 5：mx6s_capture 深入分析

目标：理解它怎样承接 V4L2、控制 Pipeline 并接收真正的视频数据。

需要讲清：

- platform probe、资源获取、Video Node 注册。
- V4L2 ioctl 回调与 VB2 回调的分工。
- 格式枚举、FourCC、Media Bus Code 和 CSI 硬件格式之间的关系。
- `STREAMON` 如何先调用 Sensor `s_stream(1)`，再启动 VB2/CSI。
- CSI 双 Buffer、DMA 地址、CSI 寄存器和中断处理。
- 中断中怎样调用 VB2 的 Buffer 完成接口。

通过标准：能够从 `VIDIOC_STREAMON` 一直讲到第一帧 CSI 中断发生。

### 阶段 6：ov5640_v3 深入分析

目标：理解 Sensor 驱动为什么主要是控制驱动，而不是搬运图像的驱动。

需要讲清：

- I2C Driver、probe、芯片 ID、寄存器表。
- `v4l2_subdev_ops` 的 core/video/pad 分组。
- 格式、分辨率、帧率和 Media Bus Code 的协商。
- `s_stream(1)`、`ov5640_start()` 与寄存器配置。
- DVP 的 PCLK、VSYNC、HREF、D[7:0] 怎样连续传输图像。
- Sensor 内部时钟和硬件状态机为什么不需要 Linux `while` 循环。

通过标准：能够区分 I2C 控制平面与 DVP 数据平面，并解释两者何时工作。

### 阶段 7：完整启动和逐帧运行链路

目标：把前六个阶段合并成一条不间断的真实调用链。

需要讲清：

- 开机 probe 与异步绑定。
- APP 初始化格式和 Buffer。
- 第一次 `STREAMON`。
- OV5640 连续输出、CSI DMA、CSI IRQ、VB2 DONE。
- `poll()` 被唤醒、`DQBUF` 返回、APP 使用、`QBUF` 归还。
- 为什么 `STREAMON` 只调用一次，而 `QBUF/DQBUF` 持续循环。

通过标准：能够从开机讲到第 N 帧采集完成，中间不跳过任何关键层。

### 阶段 8：PXP 支线、故障定位和模拟考核

目标：将采集 Pipeline 与已经完成的 PXP 显示项目连接，并训练现场回答能力。

需要讲清：

- CSI `VIDEO_CAPTURE` 与 PXP `VIDEO_OUTPUT` 两套队列。
- CSI MMAP Buffer 通过 USERPTR 交给 PXP。
- PXP 输入 S0、输出 outbuf、Framebuffer/LCDIF。
- 两个设备分别何时 `STREAMON`。
- 根据日志、sysfs、debugfs、ioctl 返回值定位问题层级。
- 快问快答、源码指认题、画图题和故障题。

通过标准：完成一轮模拟考核，并将错误答案回填到对应章节。
